AVANT DE COMMENCER

Pourquoi l'ordinateur utilise-t-il le binaire ?

Un ordinateur est construit avec des circuits électroniques. Il est pratique et fiable de distinguer deux états physiques : un état bas et un état haut. On les représente par 0 et 1. Un chiffre binaire est un bit (de l'anglais binary digit).

0

État bas

Dans le modèle simplifié du cours : absence de tension détectée.

1

État haut

Dans le modèle simplifié du cours : présence d'une tension détectée.

Les nombres, textes, images, sons et instructions doivent donc être traduits en suites de bits : c'est le codage. Deux états se distinguent plus facilement que dix états différents lorsqu'il existe du bruit électrique.

Idée essentielle : l'ordinateur ne « voit » pas directement le nombre 25 comme nous. Il manipule une représentation codée de ce nombre.

Objectifs du cours

  • Comprendre les bases 2, 8, 10 et 16.
  • Convertir un nombre d'une base à une autre.
  • Coder des entiers non signés et signés sur un nombre limité de bits.
  • Faire des additions, soustractions et décalages en binaire.
  • Comprendre la virgule fixe et les nombres flottants IEEE 754.
CHAPITRE 1

Les systèmes de numération positionnels

Avant de convertir les nombres, il faut comprendre ce qu'est une base et comment la position d'un chiffre change sa valeur.

1.1 Le vocabulaire à connaître

Bit

Un bit est une case qui contient 0 ou 1. Exemple : 1011 contient 4 bits.

Quartet / nibble

Un groupe de 4 bits. Il correspond exactement à un chiffre hexadécimal.

Octet / byte

Un groupe de 8 bits. Il possède 2⁸ = 256 combinaisons possibles.

Mot / word

Groupe de bits traité en une fois par le processeur : par exemple 16, 32 ou 64 bits selon l'architecture.

Dans 10110010, le MSB (Most Significant Bit) est le bit le plus à gauche, celui de poids fort. Le LSB (Least Significant Bit) est le bit le plus à droite, celui de poids faible.

Exemple : lire les poids

Sur 8 bits, les poids de droite à gauche sont :

1286432168421
10110010

On additionne les poids qui sont au-dessus d'un bit 1 : 128 + 32 + 16 + 2 = 178.

1.2 Le principe positionnel

Dans un système positionnel de base b, chaque position porte un poids égal à une puissance de la base. En partant de la droite, les positions commencent par 0, puis 1, puis 2, etc.

(dₙ₋₁…d₂d₁d₀)ᵦ = dₙ₋₁×bⁿ⁻¹ + … + d₂×b² + d₁×b¹ + d₀×b⁰

Exemple en base 10 : 5062

5062 = 5×10³ + 0×10² + 6×10¹ + 2×10⁰

= 5000 + 0 + 60 + 2 = 5062.

Le chiffre 5 vaut 5000 parce qu'il occupe la position des milliers. Le même chiffre en position des unités vaudrait seulement 5.

1.5 Combien de valeurs avec n bits ?

Chaque bit peut prendre deux valeurs. Avec n bits, le nombre de combinaisons est 2ⁿ. Pour un entier non signé, la plage va de 0 à 2ⁿ−1.

  • 1 bit : 2 valeurs, de 0 à 1.
  • 4 bits : 16 valeurs, de 0 à 15.
  • 8 bits : 256 valeurs, de 0 à 255.
  • 10 bits : 1024 valeurs, de 0 à 1023.

Pour représenter V valeurs distinctes, choisir le plus petit n tel que 2ⁿ ≥ V.

Exercice résolu 1

Question : combien de valeurs peut-on coder sur 6 bits ?

Étape 1 : calculer 2⁶ = 64 combinaisons.

Étape 2 : en non signé, la plage est de 0 à 64−1.

Réponse : 64 valeurs, de 0 à 63.

Exercice résolu 2

Question : combien de bits pour coder les 26 lettres ?

2⁴ = 16, trop petit. 2⁵ = 32, suffisant. Il faut donc 5 bits.

À vous d'essayer

1) Écrivez les chiffres autorisés en base 8 et en base 16. 2) Décomposez (1A3)₁₆. 3) Combien de valeurs sur 3 octets ?

Voir la correction

1) Base 8 : 0 à 7. Base 16 : 0 à 9 et A à F. 2) 1×16² + 10×16 + 3 = 256 + 160 + 3 = 419. 3) 3 octets = 24 bits, donc 2²⁴ = 16 777 216 valeurs.

CHAPITRE 2

Les conversions entre bases

Trois méthodes principales : décomposition polynomiale, divisions successives et groupements de bits.

2.1 De la base b vers la base 10 : méthode polynomiale

  1. Numéroter les positions de droite à gauche, en commençant par 0.
  2. Multiplier chaque chiffre par la base élevée à sa position.
  3. En base 16, remplacer A…F par 10…15.
  4. Additionner les termes.

Exemple A : (110101)₂ vers le décimal

110101₂ = 1×2⁵ + 1×2⁴ + 0×2³ + 1×2² + 0×2¹ + 1×2⁰

= 32 + 16 + 0 + 4 + 0 + 1 = 53.

Exemple B : (725)₈ vers le décimal

725₈ = 7×8² + 2×8¹ + 5×8⁰ = 7×64 + 2×8 + 5 = 448 + 16 + 5 = 469.

Exemple C : (3F9)₁₆ vers le décimal

F vaut 15. Donc 3F9₁₆ = 3×16² + 15×16¹ + 9×16⁰ = 768 + 240 + 9 = 1017.

2.2 De la base 10 vers une base b : divisions successives

On divise le nombre par la base cible, on note chaque reste, puis on divise le quotient obtenu. On s'arrête lorsque le quotient vaut 0. La réponse se lit du dernier reste au premier, donc de bas en haut.

Exemple : 156 en binaire

DivisionQuotientReste
156 ÷ 2780
78 ÷ 2390
39 ÷ 2191
19 ÷ 291
9 ÷ 241
4 ÷ 220
2 ÷ 210
1 ÷ 201

Lire les restes de bas en haut : 156₁₀ = 10011100₂.

Vérification : 128 + 16 + 8 + 4 = 156.

Exemple : 2026 en hexadécimal

2026 ÷ 16 = 126 reste 10 (A). 126 ÷ 16 = 7 reste 14 (E). 7 ÷ 16 = 0 reste 7.

Lecture du bas vers le haut : 2026₁₀ = 7EA₁₆. Vérification : 7×256 + 14×16 + 10 = 1792 + 224 + 10 = 2026.

2.3 Binaire vers octal : groupes de 3 bits

Parce que 8 = 2³, un chiffre octal correspond à 3 bits. Regrouper les bits depuis la droite. Ajouter des zéros à gauche si le groupe de gauche est incomplet.

Exemple : 10110111₂ vers l'octal

Regrouper : 010 | 110 | 111 → 2 | 6 | 7. Donc 10110111₂ = 267₈.

Dans l'autre sens, remplacer chaque chiffre octal par 3 bits : 524₈ → 5=101, 2=010, 4=100 → 101010100₂.

2.4 Binaire vers hexadécimal : groupes de 4 bits

Parce que 16 = 2⁴, un chiffre hexadécimal correspond à 4 bits. Regrouper depuis la droite, compléter à gauche si nécessaire, puis traduire chaque groupe grâce à la table 0–F.

Exemple

1101 0110 1010 1111 → D | 6 | A | F. Donc (1101011010101111)₂ = (D6AF)₁₆.

2.5 Résumé : choisir la bonne méthode

  • Base b → base 10 : décomposition polynomiale.
  • Base 10 → base b : divisions successives.
  • Binaire ↔ octal : groupes de 3 bits.
  • Binaire ↔ hexadécimal : groupes de 4 bits.
  • Pour vérifier, reconvertir le résultat en décimal.

Exercice résolu complet

Convertir 200 en binaire puis en hexadécimal.

Correction pas à pas

200 = 128 + 64 + 8. En plaçant les bits selon les poids 128, 64, 32, 16, 8, 4, 2, 1, on obtient 11001000₂. Pour l'hexa : 1100 | 1000 → C | 8, donc C8₁₆.

À vous d'essayer

1) Convertir 214₁₀ en binaire. 2) Convertir 10110111₂ en octal et en hexadécimal. 3) Convertir 234₈ en décimal.

Voir la correction

1) 214 = 128+64+16+4+2 → 11010110₂. 2) Octal : 010|110|111 = 267₈. Hexa : 1011|0111 = B7₁₆. 3) 2×64 + 3×8 + 4 = 156₁₀.

CHAPITRE 3

La représentation des entiers en machine

3.1 Un nombre de bits limité

Une représentation utilise un nombre fixe de bits. Un octet contient 8 bits et 256 combinaisons. Les unités de stockage doivent être distinguées :

  • 1 ko (kilooctet décimal) = 1000 octets ; 1 Mo = 10⁶ octets ; 1 Go = 10⁹ octets ; 1 To = 10¹² octets.
  • 1 Kio (kibioctet binaire) = 1024 octets ; 1 Mio = 2²⁰ octets ; 1 Gio = 2³⁰ octets ; 1 Tio = 2⁴⁰ octets.

Un disque vendu comme 1 To contient 10¹² octets, soit environ 0,909 Tio. L'écart d'affichage vient de la différence entre les unités, pas nécessairement d'une perte de données.

3.2 Entiers non signés (unsigned)

Pour un entier non signé, aucun bit ne sert à représenter un signe : tous les bits représentent la valeur. Sur n bits :

Minimum = 0 · Maximum = 2ⁿ − 1 · Nombre de valeurs = 2ⁿ

Sur 8 bits, 00000000 = 0 et 11111111 = 255 : 256 valeurs sont possibles. Exemples d'usages : compteurs, indices, tailles et composantes RVB d'une couleur (0 à 255).

3.3 Plages usuelles

3.4 Le débordement (overflow)

Si le résultat nécessite plus de bits que la taille disponible, les bits en trop ne peuvent pas être conservés. Pour un calcul non signé sur 8 bits, seul l'octet de droite reste stocké.

Exemple : 250 + 10 sur 8 bits non signés

250 = 11111010₂ et 10 = 00001010₂.

11111010 + 00001010 = 1 00000100 (260 en valeur mathématique).

Le bit supplémentaire à gauche est perdu. Les 8 bits restants sont 00000100 = 4. C'est un débordement.

Sur 8 bits non signés, 255 + 1 devient 0 : c'est l'arithmétique modulo 2⁸. Pour éviter un débordement, on peut utiliser un type plus large ou vérifier la valeur avant le calcul. Le cours cite le bug de l'an 2038 et l'accident Ariane 5 (vol 501, 1996) comme exemples historiques liés aux limites de représentation numérique.

Exercice résolu : taille d'une image RVB

Image 640 × 480, 3 octets par pixel.

Nombre de pixels = 640×480 = 307 200. Taille = 307 200×3 = 921 600 octets. En Kio : 921 600÷1024 = 900 Kio, soit environ 0,88 Mio.

À vous d'essayer

1) Quelle est la plage non signée sur 12 bits ? 2) Combien de bits faut-il pour 1000 valeurs ? 3) Que donne 250+10 sur 8 bits non signés ?

Voir la correction

1) 2¹² = 4096 valeurs, donc 0 à 4095. 2) 2⁹=512 trop petit ; 2¹⁰=1024 suffisant : 10 bits. 3) 260 dépasse 255 ; le résultat stocké est 00000100 = 4.

CHAPITRE 4

La représentation des entiers négatifs

Un circuit ne stocke que des bits. Il faut donc une convention pour coder le signe. Trois méthodes sont étudiées : signe et valeur absolue (SVA), complément à 1 et complément à 2.

4.1 Les exigences

Un bon codage doit permettre de reconnaître le signe, éviter deux représentations du zéro et faciliter les additions/soustractions. Dans ces trois conventions, le bit de poids fort (MSB) sert de bit de signe : 0 pour positif, 1 pour négatif.

4.2 Méthode 1 : signe et valeur absolue (SVA)

Le MSB donne le signe et les n−1 bits restants codent la valeur absolue en binaire.

Sur 8 bits : +45 = 00101101 ; −45 = 10101101.

Avantage : lecture intuitive. Inconvénients : deux zéros existent (00000000 = +0 et 10000000 = −0) et l'addition ne fonctionne pas directement pour tous les signes. Sur 8 bits, la plage va de −127 à +127, avec deux codages du zéro.

4.3 Méthode 2 : complément à 1

Pour obtenir l'opposé, inverser chaque bit : chaque 0 devient 1 et chaque 1 devient 0.

+45 = 00101101. Inversion → −45 = 11010010.

L'addition fonctionne presque, mais il faut traiter le report sortant en le réajoutant au résultat (report circulaire). Il existe toujours deux zéros : 00000000 et 11111111.

Exemple : (+5) + (−3) en complément à 1

+5 = 00000101. +3 = 00000011, donc −3 = 11111100.

00000101 + 11111100 = 1 00000001. Ajouter le report sortant 1 au résultat : 00000001 + 1 = 00000010 = +2.

4.4 Méthode 3 : complément à 2 (la méthode utilisée)

Le complément à 2 permet d'utiliser le même additionneur pour additionner et soustraire, sans double zéro. Pour coder −N sur n bits :

  1. Écrire la valeur absolue N en binaire sur n bits.
  2. Inverser tous les bits (complément à 1).
  3. Ajouter 1.

Exemple : coder −25 sur 8 bits

25 = 00011001.

Inversion : 11100110.

Ajouter 1 : 11100111.

Donc −25 = 11100111₂ (E7 en hexadécimal).

Astuce rapide : en partant de la droite, recopier les bits jusqu'au premier 1 inclus, puis inverser tous les bits situés à sa gauche.

4.5 Lire un nombre en complément à 2

  • Si le MSB vaut 0, le nombre est positif ou nul : convertir normalement.
  • Si le MSB vaut 1, le nombre est négatif : inverser les bits et ajouter 1 pour retrouver la valeur absolue, puis mettre le signe −.

Autre méthode de calcul rapide sur n bits : pour un mot dont le MSB vaut 1, sa valeur signée est sa valeur non signée moins 2ⁿ.

Exemple : décoder 11001010 sur 8 bits

En non signé : 128 + 64 + 8 + 2 = 202.

En complément à 2 : MSB=1, donc nombre négatif. 202 − 256 = −54.

Vérification par complément : inversion 00110101, +1 → 00110110 = 54, donc −54.

4.6 Plage en complément à 2

Minimum = −2ⁿ⁻¹ · Maximum = 2ⁿ⁻¹ − 1

Sur 8 bits : −128 à +127, soit 256 valeurs utiles et un seul zéro. Quelques motifs :

CHAPITRE 5

Les opérations arithmétiques en binaire

Le processeur s'appuie sur des circuits d'addition. La soustraction peut être transformée en addition grâce au complément à 2.

5.1 Règles de l'addition binaire

CalculRésultat binaireÀ comprendre
0 + 00Pas de retenue
0 + 11Pas de retenue
1 + 01Pas de retenue
1 + 110Écrire 0, retenir 1
1 + 1 + 111Écrire 1, retenir 1

Comme en décimal, on additionne colonne par colonne de droite à gauche. En binaire, on retient dès que la somme atteint 2.

Exemple : 11 + 13

11 = 1011, 13 = 1101.

   1011
 + 1101

  11000

11000₂ = 16 + 8 = 24.

5.2 Soustraction par complément à 2

A − B = A + (complément à 2 de B)

Étapes : écrire B sur la taille choisie, inverser ses bits, ajouter 1, puis additionner à A. Si un report sort à gauche de la taille disponible, on l'ignore.

Exemple : 60 − 35 sur 8 bits

60 = 00111100. 35 = 00100011.

Inversion de 35 : 11011100, puis +1 : −35 = 11011101.

  00111100
+ 11011101
----------
1 00011001

Ignorer le report extérieur : 00011001 = 25.

5.3 Débordement signé : carry et overflow

Pour des entiers signés en complément à 2, il y a débordement lorsque deux opérandes de même signe donnent un résultat de signe opposé.

Exemple : +100 + +50 sur 8 bits signés

La somme mathématique vaut 150, mais la plage signée sur 8 bits est −128 à +127. Le motif obtenu est 10010110, interprété comme −106. Deux positifs ont produit un négatif : overflow signé.

Carry ≠ Overflow : le carry (report sortant, indicateur CF) concerne le débordement non signé. L'overflow (indicateur OF) concerne le débordement signé. Un report peut exister sans overflow signé, et inversement.

5.4 Multiplication et division binaires

La multiplication binaire se fait comme la multiplication décimale, avec des chiffres 0 et 1 : multiplier par 0 donne une ligne de zéros ; multiplier par 1 recopie le nombre. Les lignes sont décalées puis additionnées.

Exemple : 1011₂ × 101₂

1011₂ = 11 et 101₂ = 5. Donc 11×5 = 55. En binaire, le résultat est 110111₂.

Pour la division, on applique le principe de la division posée. Exemple : 1101₂ ÷ 10₂ → quotient 110, reste 1, soit 13 ÷ 2 = 6 reste 1.

5.5 Décalages de bits

  • Décalage logique à gauche de k positions (<< k) : multiplie par 2ᵏ si aucun bit significatif n'est perdu et dans les limites du type.
  • Décalage logique à droite (>> k pour un non signé) : division entière par 2ᵏ.
  • Décalage arithmétique à droite d'un nombre signé : recopie le bit de signe pour préserver le signe.

Exemple : décaler 00010110

00010110₂ = 22. Vers la gauche d'un rang : 00101100 = 44. Vers la gauche de deux rangs : 01011000 = 88.

Vers la droite d'un rang : 00001011 = 11. Encore un rang : 00000101 = 5 (division entière).

Décalage arithmétique signé

11110000 représente −16 en complément à 2 sur 8 bits. Décalage arithmétique à droite d'un rang : 11111000, qui représente −8.

À vous d'essayer

1) Calculer 01001101 + 00110110. 2) Calculer 60−35 en complément à 2. 3) Décaler 00010110 de deux rangs à gauche. 4) Décaler arithmétiquement 11110000 à droite d'un rang. 5) Que se passe-t-il avec (−100)+(−50) sur 8 bits signés ?

Voir la correction

1) 10000011 = 131 non signé ; deux positifs donnent un motif négatif en signé (−125) : overflow signé. 2) 00011001 = 25, report extérieur ignoré. 3) 01011000 = 88. 4) 11111000 = −8. 5) 10011100 + 11001110 = 1 01101010 ; en conservant 8 bits : 01101010 = +106, alors que deux négatifs ont donné un positif : overflow.

CHAPITRE 6

Les nombres fractionnaires

Les entiers ne suffisent pas pour représenter des nombres comme 3,14 ou 0,001. Deux stratégies sont présentées : la virgule fixe et la virgule flottante.

6.1 Les poids de part et d'autre de la virgule

À gauche de la virgule binaire, les poids sont 2⁰, 2¹, 2²… (1, 2, 4, 8…). À droite, ils sont 2⁻¹, 2⁻², 2⁻³… (0,5 ; 0,25 ; 0,125…).

Exemple : (101,101)₂

= 1×2² + 0×2¹ + 1×2⁰ + 1×2⁻¹ + 0×2⁻² + 1×2⁻³

= 4 + 0 + 1 + 0,5 + 0 + 0,125 = 5,625.

6.2 Virgule fixe

La position de la virgule est décidée à l'avance. On réserve un nombre fixe de bits à la partie entière et à la partie fractionnaire. Par exemple, le format Q4.4 utilise 4 bits pour la partie entière et 4 bits pour la partie fractionnaire (la convention exacte du signe dépend du format utilisé).

Exemple : (1101,1011)₂

Partie entière : 1101₂ = 8 + 4 + 1 = 13.

Partie fractionnaire : .1011₂ = 1×0,5 + 0×0,25 + 1×0,125 + 1×0,0625 = 0,6875.

Total : 13,6875. Avec 4 bits fractionnaires, le pas de représentation vaut 2⁻⁴ = 0,0625.

6.3 Convertir une fraction décimale en binaire

Pour convertir la partie fractionnaire, multiplier la fraction par 2, noter la partie entière obtenue (0 ou 1), puis recommencer avec la nouvelle partie fractionnaire. Lire les bits dans l'ordre où ils sont obtenus, du premier au dernier. On s'arrête lorsque la fraction devient 0 ou lorsqu'on atteint la précision voulue.

Exemple : convertir 0,6875

OpérationPartie entière (bit)Nouvelle fraction
0,6875×2 = 1,37510,375
0,375×2 = 0,7500,75
0,75×2 = 1,510,5
0,5×2 = 1,010

Les bits obtenus sont 1, 0, 1, 1 : 0,6875₁₀ = 0,1011₂.

Attention : pour convertir une partie entière, on lit les restes des divisions de bas en haut ; pour une partie fractionnaire, on lit les bits des multiplications dans leur ordre d'obtention.

6.4 Virgule fixe : avantages et limites

Avantages : calculs rapides, circuits simples et pas de représentation constant. Limites : plage limitée et difficulté à représenter dans le même format des nombres extrêmement grands et extrêmement petits. Le cours donne comme contraste la masse d'un électron (environ 9×10⁻³¹ kg) et la distance Terre–Soleil (environ 1,5×10¹¹ m).

6.5 Virgule flottante et normalisation

La virgule flottante permet à la virgule de se déplacer. On représente le nombre sous la forme :

N = (−1)ˢ × M × 2ᵉ, avec 1 ≤ M < 2
  • Signe S : 0 si le nombre est positif, 1 s'il est négatif.
  • Mantisse significative M : les chiffres significatifs, normalisés sous la forme 1,xxxxx en binaire.
  • Exposant e : indique la puissance de 2.

Normaliser un nombre

1101,1011₂ = 1,1011011₂ × 2³ : on déplace la virgule de 3 positions vers la gauche.

0,00101₂ = 1,01₂ × 2⁻³ : on déplace la virgule de 3 positions vers la droite, donc l'exposant est −3.

6.6 IEEE 754 simple précision (32 bits)

Le format simple précision utilise 32 bits répartis ainsi :

Signe
1 bit
Exposant
8 bits
Mantisse stockée
23 bits
  • Le premier bit est le signe S.
  • Les 8 bits suivants stockent un exposant biaisé.
  • Les 23 derniers bits stockent la fraction de la mantisse.

Pour un nombre normalisé, le 1 situé avant la virgule binaire est implicite (le « bit caché »). Il n'est pas stocké : la précision significative est donc 23+1 = 24 bits, soit environ 7 chiffres décimaux.

E stocké = e réel + 127 · e réel = E stocké − 127

Pour les nombres normalisés, la valeur est (−1)ˢ × 1,M × 2⁽ᴱ⁻¹²⁷⁾. Les exposants stockés tout à 0 ou tout à 1 sont réservés à des cas particuliers ; la plage approximative des nombres normalisés est de 1,2×10⁻³⁸ à 3,4×10³⁸.

Exemple complet : coder −13,6875

  1. Conversion binaire : 13,6875 = 1101,1011₂.
  2. Normalisation : 1,1011011₂ × 2³.
  3. Signe : nombre négatif, donc S=1.
  4. Exposant : e=3, donc E=3+127=130=10000010.
  5. Mantisse : les bits après le 1 initial sont 1011011, complétés par des zéros jusqu'à 23 bits.

Mot binaire : 1 10000010 10110110000000000000000. Écriture hexadécimale : 0xC15B0000.

6.7 Double précision (64 bits)

Le format double précision utilise 64 bits : 1 bit de signe, 11 bits d'exposant et 52 bits de mantisse stockée. Son biais d'exposant est 1023. La valeur normalisée s'écrit (−1)ˢ × 1,M × 2⁽ᴱ⁻¹⁰²³⁾. Le type flottant usuel est généralement double précision en Python et JavaScript.

6.8 Cas particuliers et erreurs d'arrondi

IEEE 754 prévoit notamment NaN (« Not a Number ») pour des opérations indéfinies comme 0/0, ∞−∞ ou la racine carrée d'un nombre négatif dans les nombres réels. Une propriété inhabituelle est NaN != NaN.

Certains nombres décimaux, comme 0,1, n'ont pas d'écriture binaire finie. Ils sont stockés avec une approximation. Ainsi, dans de nombreux langages, 0.1 + 0.2 peut afficher 0.30000000000000004. Ce n'est pas nécessairement une erreur de l'addition : c'est une conséquence de la représentation finie.

Exercice résolu : coder 6,625 en IEEE 754 simple précision

6 = 110₂. Fraction : 0,625×2=1,25 → bit 1 ; 0,25×2=0,5 → bit 0 ; 0,5×2=1,0 → bit 1. Donc 6,625 = 110,101₂.

Normalisation : 1,10101₂ × 2². S=0. Exposant biaisé E=2+127=129=10000001. Mantisse : 10101 suivie de 18 zéros.

Résultat : 0 10000001 10101000000000000000000 = 0x40D40000.

À vous d'essayer

1) Convertir 6,625 en binaire. 2) Normaliser le résultat. 3) Quel est le biais pour un exposant de 5 bits ? 4) Décoder 0 10000010 01000000000000000000000.

Voir la correction

1) 6=110₂ et 0,625=0,101₂ ; donc 110,101₂. 2) 1,10101₂×2². 3) Biais = 2⁽ᵏ⁻¹⁾−1 = 2⁴−1 = 15. 4) S=0, E=130 donc e=130−127=3 ; M=1,01₂=1,25 ; valeur = 1,25×2³ = +10.

À MÉMORISER

Fiche de révision

  • Base b → décimal : multiplier chaque chiffre par b à la puissance de sa position et additionner.
  • Décimal → base b : divisions successives ; lire les restes de bas en haut.
  • Binaire → octal : grouper par 3 bits depuis la droite.
  • Binaire → hexadécimal : grouper par 4 bits depuis la droite.
  • Non signé sur n bits : de 0 à 2ⁿ−1.
  • Complément à 2 sur n bits : de −2ⁿ⁻¹ à 2ⁿ⁻¹−1.
  • Coder un négatif en C2 : inverser les bits et ajouter 1.
  • Soustraction : A−B = A + C2(B) ; ignorer le report sortant hors de la taille.
  • Overflow signé : mêmes signes en entrée, signe différent en sortie.
  • Virgule flottante : signe, exposant biaisé et mantisse.
  • Biais IEEE 754 : 127 en simple précision (8 bits d'exposant), 1023 en double précision (11 bits).
Conseil de méthode : écrivez toujours la base, la taille en bits et les étapes intermédiaires. Vérifiez les conversions en revenant à la base 10, et vérifiez les nombres signés en contrôlant le bit de signe et la plage représentable.
